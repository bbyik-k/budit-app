# 성분 명칭 변형 처리 방식 — "레티놀" vs "레티놀(500IU/g)"

> 작성일: 2026-08-07. 동일 성분의 미세하게 다른 표기가 어떻게 동일 성분으로 인식되는지에 대한 코드·실측 검증 기록.
> 결론: **예시의 `레티놀(500IU/g)`은 현재 구조에서 동일 성분으로 인식되지 못한다** (4단계 매칭 전부 실패, 실측 확인).

---

## 명칭이 표준화되는 두 가지 경로

### 경로 A — 제품(시드) 데이터: 사람이 미리 매핑 (매칭 로직을 타지 않음)

`toy_product_ingredients.csv`가 CSV 제작 시점에 두 컬럼을 분리해 둔다:

| 컬럼              | 내용                             | 예시            |
| ----------------- | -------------------------------- | --------------- |
| `raw_name`        | 제품 전성분 표기 원문            | 레티놀(500IU/g) |
| `ingredient_name` | 표준명 (`ingredients.name` 참조) | 레티놀          |

시드 시 DB `product_ingredients`에는 표준 성분 FK(`ingredient_id`) + 원문(`raw_name`)이 함께 저장되고, 분석 시에는 표준명으로만 조회한다 (app/api/analyze/route.ts:77–79). **제품 경로에서는 명칭 변형 문제가 애초에 발생하지 않는다** — 정규화가 데이터 제작 단계에서 수동으로 끝나 있기 때문.

### 경로 B — 사용자 직접 입력: 4단계 매칭 (lib/analyze/match.ts)

| 단계         | 처리                                                                                            | 근거                           |
| ------------ | ----------------------------------------------------------------------------------------------- | ------------------------------ |
| 0. 전처리    | `normalizeName()` — 괄호 안이 **숫자·소수점·공백·%뿐일 때만** 괄호째 제거, 연속 공백 정리, trim | lib/ingredients/normalize.ts:9 |
| 1. 정확 일치 | `ingredients.name`과 완전 일치                                                                  | lib/analyze/match.ts:35–38     |
| 2. 별칭 일치 | `ingredient_aliases.alias`와 완전 일치                                                          | lib/analyze/match.ts:56–59     |
| 3. 유사도    | `match_ingredient_fuzzy` RPC, pg_trgm similarity ≥ **0.9**                                      | lib/analyze/match.ts:86–90     |
| 4. 실패 기록 | `unmatched_log`에 upsert (occurrence_count 증가)                                                | lib/analyze/match.ts:106–114   |

## 예시 검증: `레티놀(500IU/g)` 은 4단계 모두 실패한다

| 단계         | 결과                 | 검증 내용                                                                                                                                              |
| ------------ | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 0. 전처리    | ❌ 통과 못함         | 정규식 `[\(\[\{][\d.\s]*%?\s*[\)\]\}]`은 괄호 안에 문자가 있으면 매칭 안 됨. 실행 검증: `레티놀(2%)` → `레티놀` ✅ / `레티놀(500IU/g)` → **그대로** ❌ |
| 1. 정확 일치 | ❌                   | `레티놀(500IU/g)` ≠ `레티놀`                                                                                                                           |
| 2. 별칭      | ❌                   | alias 사전 등록분은 `비타민A`, `Retinol`, `레티노이드` → 레티놀 뿐 (data/csv/ingredient_aliases.csv:7–9). 농도 표기 변형은 미등록                      |
| 3. 유사도    | ❌                   | 실제 DB RPC 실측: `similarity("레티놀(500IU/g)", "레티놀") = 0.33` → 임계값 0.9에 한참 미달                                                            |
| 4. 결과      | `unmatched_log` 기록 | 매칭 실패로 미매칭 처리                                                                                                                                |

### 동일 성분으로 묶이는 경우는 세 가지뿐

1. **숫자+% 형태의 농도 표기** — `(2%)`, `[0.5%]` 등은 전처리에서 제거됨
2. **alias 사전에 등록된 표기** — 비타민A, Retinol, 레티노이드 등
3. **유사도 0.9 이상인 변형** — 임계값이 높아 사실상 한두 글자 차이(오타 수준)만 허용

## 검증 과정에서 확인된 모순 2건 (사실 기록)

1. **UI 문구와 서버 동작 불일치**: 직접 입력 다이얼로그는 "미매칭 (n) — **분석에는 포함됩니다**"라고 안내하지만(components/analyze/manual-input-dialog.tsx:146), 서버의 `resolveSlotNames()`는 **매칭된 성분명만** 반환하므로(app/api/analyze/route.ts:97–99) 미매칭 성분은 실제로는 분석에서 제외된다.
2. **README API 예시가 실제로 재현되지 않음**: README.md의 `/api/ingredients/match` 예시는 `레티놀(500IU/g)` → `레티놀` matched를 보여주지만(README.md:144–149), 위 검증대로 이 입력은 현재 코드에서 매칭에 실패한다.
